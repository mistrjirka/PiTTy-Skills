# Component-specific questions

Use the relevant row, not every pattern on every task.

| Component | Questions worth answering |
|---|---|
| Form | What is required, how is invalid input explained, and what happens while saving or after failure? |
| Table/dashboard | Which comparisons/actions matter, how does growing data load, and what do empty/stale/error states mean? |
| Navigation/search | Can users locate and revisit the task, clear filters and understand no-results states? |
| Dialog | What opens/closes it, where does focus go, and could dismissal lose important work? |
| Settings | What is current, pending or saved, and are consequential changes reversible or explicitly confirmed? |
| Onboarding | What minimum outcome enables real use, and is skip/resume appropriate? |
| AI interface | What is generated, what evidence supports it, and how can the user correct or decline it? |

Reuse project components and actual interaction conventions. Field/column/menu counts, mandatory wizards, celebrations and decorative empty-state illustrations are not correctness rules. Avoid new abstractions until repeated behavior or ownership justifies them.
