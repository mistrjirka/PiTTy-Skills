# Prompt change evaluation record

Use the project's existing evaluation location, not a mandatory new task ledger.

Record the exact model/provider/version, prompt revision, tools, permissions, reasoning setting, input cases and baseline results. Test one change group at a time. Use both genuine failures and correct near-neighbors to expose false positives.

Compare task outcome and required evidence before efficiency. Record missed root causes, unsupported findings, broken action boundaries, dropped requirements and incomplete final answers. For multi-agent changes, also record per-role tool time and verification work; equal prompt length is not equal workload.

A dry-run simulation is useful for prompt ambiguity, but it is not a real tool execution or measured production success. Label unrun tests and unavailable metrics explicitly.
